# 이관 검증 기록

검증일: 2026-10-20 (한국시간)

## 출처와 차이

- 원본 실제 Sites 관리 Git 저장소에 owner 권한으로 접근했습니다. 공개 페이지 HTML 추출은 사용하지 않았습니다.
- 게시 버전 8, 원본 커밋 `49149d1bf93d5af59616132572d90af9612f6786`, 배포 `appgdep_6ad57ea4aa04819180d793d331ff67de`의 상태가 `succeeded`임을 조회했습니다.
- 게시 커밋의 실행 코드·이미지·라이브러리 11개 파일과 PC 앱 파일의 SHA-256이 모두 일치했습니다. 원본 Sites 설정 파일까지 합치면 추적 소스는 12개입니다. 미게시 앱 수정은 없습니다.
- 이관 저장소의 `dist/` 11개 파일은 원본과 바이트 단위로 일치합니다. 출처 목록/해시는 `source-provenance.json`에 있습니다.
- 추가한 파일은 README/출처/라이선스 안내, 로컬 실행·검증 스크립트, npm manifest/lock, `.env.example`, Git 제외 규칙입니다. 활성 Sites 설정에서 원 계정의 project_id를 제거했고 출처 문서에는 기록했습니다. 앱 코드는 수정하지 않았습니다.

## 실행·빌드

- Node.js 24: JavaScript 문법 검사, HTML에서 참조하는 자산, 코드에서 참조하는 이미지와 JSON 설정 읽기 확인.
- 로컬 HTTP 서버의 index 응답 200 확인.
- Chrome headless: 8단계 화면 전환, 창호명 Enter 이동, 내창 단창 F-130I 자동선택, 터닝도어 빈 치수, 핸들 중앙 기본값과 580 경계 활성화 확인.
- XLSX 및 JPG 실제 다운로드 성공. 다운로드 파일과 검증용 상담값은 Git에서 제외했습니다.
- 390px 화면에서 문서 가로 넘침 없음. 브라우저 JS 오류 및 자산 HTTP 오류 없음.
- 앱은 빌드 없는 정적 소스이므로 컴파일 단계는 없습니다. `npm run build`는 `node scripts/check.mjs`와 같은 검증을 실행합니다.
- 현재 실행환경에 npm CLI가 없어 `npm ci` 자체는 실행하지 않았습니다. npm 외부 의존성은 없고 Node 명령으로 실행/검증을 완료했습니다. package/lock 버전·이름·Node engines의 일치도 확인했습니다.

## 보안·데이터

- 추출 범위는 관리 저장소의 `dist/`와 비밀값 없는 배포 구조입니다. 로컬 개인문서, 이전 대화 원문, 백업, HWP, 검증 출력과 기존 `.git` 이력은 복사하지 않았습니다.
- API 키·PAT·비밀번호·토큰 형식, 개인 연락처·이메일 형식 및 인증파일을 검사했습니다. Sites/GitHub 실행 자격증명은 소스에 넣지 않았습니다.
- 앱 상태가 빈 현장명/주소/비고와 빈 창호명으로 시작하는 것을 확인했습니다. 주소의 placeholder는 기존 앱의 가상 아파트 예시입니다. 실제 상담 기록은 포함하지 않았습니다.
- DB·클라우드 파일 저장소·서비스 계정·서버 API가 없으므로 DB 마이그레이션은 없습니다.

## 미검증과 별도 설정

- 실제 카카오톡 수신자 전송, OS 클립보드 붙여넣기, Microsoft Excel에서 인쇄, B 계정의 새 사이트 배포는 수행하지 않았습니다.
- 브라우저/OS마다 이미지 공유·복사 지원이 다르며 미지원 시 파일 다운로드로 대체합니다.
- B의 Sites 계정에서 새 project_id, 배포 접근권한, URL/도메인을 별도로 생성해야 합니다. 원본 사이트의 도메인·소유권·운영 상태는 변경하지 않았습니다.
- GitHub와 Sites 자동 동기화는 구성하지 않았습니다. 이후 수정은 명시적으로 commit/push하고 각 사이트 배포를 별도로 진행합니다.

## GitHub 업로드 상태

- 로컬 main 커밋 생성 완료. GitHub push는 인증 부재(Cannot prompt / unable to get password)로 실패했습니다. 연결된 GitHub CLI 또는 쓰기 토큰 환경변수도 없어 전체 ZIP과 업로드 절차로 인계합니다.
- 초기 원격은 비어 있었고 강제 push를 사용하지 않았습니다. 인증 절차는 GITHUB_UPLOAD.md에 있습니다.
